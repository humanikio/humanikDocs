The HumanikOS API is an HTTP interface to the same control plane the console
uses. It creates offices, dispatches work, reads and writes the data plane,
manages contacts and calendars, and drives cloud browsers.

Every route is mounted under a single version prefix:

```
/api/v1
```

## Before you start

You need two things:

1. A **workspace**. Create one in the console if you do not have one yet.
2. A **service account API key**, which starts with `hsk_`. See
   [Authentication](/docs/authentication).

## What the API covers

The public surface is scoped to what a service account key can reach. Console
only routes, webhook receivers, and internal service routes sit outside it and
are not documented here.

## Conventions used throughout

Every response is wrapped in an envelope, every request can carry a correlation
ID, and rate limits are applied per tenant. Those behaviours are identical on
every endpoint, so they are documented once rather than repeated:

## Versioning

`v1` is the only version and has never been revised. New fields and new
endpoints are added without a version change, so a client must ignore response
fields it does not recognise.
