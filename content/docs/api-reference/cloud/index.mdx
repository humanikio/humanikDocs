[web services](/docs/cloud/web-services). **An office is one of them.**

## An office is a service

An office exists on Humanik Cloud as a service of type `cloudClaw`. That is not
trivia. It is why an office can be resized, given an idle timeout, inspected for
running instances, and read for logs at all.

It also means the same setting is reachable two ways:

| | Office route | Cloud route |
| --- | --- | --- |
| Path | `/offices/{officeId}/cloud/config` | `/cloud/services/{serviceId}/userConfig` |
| Reaches | One office | Any service in the tenant |
| Permission | `instance:manage` @ that office | `cloud:manage` @ console |

**Prefer the office route.** It is narrower, and it can be granted to someone
responsible for one employee without giving them the whole cloud.

Use these endpoints when you are managing services that are not offices, or when
you want a tenant wide view. Filtering
[List services](/docs/api-reference/cloud/services/listCloudServices) to
`cloudClaw` gives you every office machine and the service ID behind it.

## Authentication is the same as everywhere else

Your ordinary service account key, plus `cloud:read` or `cloud:manage` at
`console` scope. There is no separate cloud credential to obtain.

<Callout>
  HumanikOS holds a Humanik Cloud key on your tenant's behalf and uses it to make
  these calls for you. You never see it and never send it. Every call that names
  a service, cron or secret is checked against your own account, and one that
  belongs to another account is answered with `404`, the same as one that does
  not exist.
</Callout>

If your tenant has never used Humanik Cloud, the account is provisioned on the
first call and the request retries. A first call may be slower than later ones.
That is not an error.

## Responses come from Humanik Cloud unchanged

These endpoints forward to Humanik Cloud and return its response verbatim. Two
consequences:

- **Error wording differs** from the rest of this API. Branch on the status code.
- **`502` means we could not reach Humanik Cloud**, not that your request was
  wrong.

## Crons and secrets

**Crons** run work on a service on a schedule: an HTTP request, or a command on a
web service. Start at
[List crons](/docs/api-reference/cloud/crons/listCloudCrons).

**Secrets** are encrypted values a service reads when its machine starts, for
one service or for the whole account. Start at
[List secrets](/docs/api-reference/cloud/secrets/listCloudSecrets).

| To | You need |
| --- | --- |
| List crons, secrets and secret field names | `cloud:read` @ `console` |
| Create, change, run or delete a cron or secret | `cloud:manage` @ `console` |
| **Read a secret's value** | `cloud:manage` @ `console` |

Reading a value needs `cloud:manage`, not `cloud:read`, so a read only role can
see which secrets exist without seeing what is in them.

## API keys

There is no Humanik Cloud key for you to obtain or copy. HumanikOS holds your
account's key, encrypted, and uses it for you; every person and service account
reaches the cloud through these endpoints with their own role. A key can never
be viewed, through the console or the API.

| To | Use | You need |
| --- | --- | --- |
| See the keys and which one is in use | [List API keys](/docs/api-reference/cloud/api-keys/listCloudApiKeys) | `cloud:read` @ `console` |
| Replace the key in use | [Rotate the key](/docs/api-reference/cloud/api-keys/rotateCloudApiKey) | `cloud:manage` @ `console` |
| Remove a key that is not in use | [Revoke an API key](/docs/api-reference/cloud/api-keys/revokeCloudApiKey) | `cloud:manage` @ `console` |

**After a rotation the old key keeps working for 24 hours**, so offices that are
running are not cut off. They pick up the new key the next time they start.

## Two things not to do here

**Do not create an office as a service.**
[Create an office](/docs/api-reference/offices/offices/createOffice) provisions
its service along with its identity, vault, and data plane entry. A bare
`cloudClaw` service has none of that.

**Do not delete an office's service.**
[Delete the office](/docs/api-reference/offices/offices/deleteOffice) instead.
Deleting the service alone leaves an office whose machine no longer exists.
