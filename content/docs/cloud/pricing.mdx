title: Pricing
description: What every machine on Humanik Cloud costs per hour and per month, exactly which time is billed, how it is charged to your credit, and worked examples.
---

On Humanik Cloud you pay for one thing: **the time a machine is running**, at the
hourly price of its size. A machine that is asleep costs nothing to run. There is
no charge per request, per deploy or per service.

Machine time is paid from the same prepaid
[credit balance](/docs/spend/credit) as model use. It is taken once an hour, as
described in [How you are charged](#how-you-are-charged). No
[budget](/docs/spend/budgets) counts it. See [Billing and budgets](/docs/spend)
for how the two fit together.

## The rule

```
cost = time a machine runs × the hourly price of its size
```

- **Each machine is billed on its own.** Two machines running for one hour cost
  two hours.
- **Time is measured exactly.** There is no minimum and no rounding up to the
  hour. A machine that runs for 12 minutes is billed for 12 minutes.
- **Prices are in US dollars**, per machine, per hour it runs.

## Prices

The monthly column is a machine that runs all month (730 hours) and never sleeps.
Most services sleep when idle and cost much less. See the
[worked examples](#worked-examples).

### Web services

A web service picks vCPU and memory separately, so its price is built from three
parts:

| Part | Per hour |
| --- | --- |
| Each vCPU | $0.04857 |
| Each GB of memory | $0.00534 |
| Each running machine | $0.0075 |

```
per hour = vCPU × $0.04857 + GB × $0.00534 + $0.0075
```

For the default size, 1 vCPU with 2 GB: $0.04857 + 2 × $0.00534 + $0.0075 =
**$0.0668 per hour**.

## Which time is billed

Billing for a machine starts when the machine is started and stops when it is
stopped. Every moment in between is billed, whether or not the machine is doing
work.

| A machine starts when | A machine stops when |
| --- | --- |
| A request or message arrives for a service with no machine running | Its [idle timeout](/docs/cloud/scaling#idle-timeout) runs out |
| You deploy or restart a service | You deploy or restart the service, which replaces it |
| | You shut it down |
| | A deploy fails and its new machine is stopped |
| | The machine stops unexpectedly |

**Starting up is billed.** A machine is billed from the moment it starts, not
from the moment it is ready. An office restoring its files, or a web service
cloning, installing and building before it answers, is billed for those minutes.

**Waiting for the idle timeout is billed.** After its last piece of work, a
machine stays awake for its idle timeout before it stops. A 20 minute timeout
adds up to 20 minutes to every burst of work.

**A deploy or restart ends the old machine's time at once.** The old machine's
billing stops when it is stopped, and the new machine's starts with it.

## The price is fixed when a machine starts

A machine is billed at the price of its size at the moment it starts, for as long
as it runs. Changing a service's size does not change the price of a machine that
is already running. The new price applies to the next machine started.

The same is true of a change to our prices: a machine already running keeps the
price it started with.

## How you are charged

Machine time is measured for each machine on its own, and taken from your credit
once an hour.

1. **Each hour is charged about 2 minutes after it ends.** All the machine time
   your account used in that hour is taken from your credit balance as one
   hourly charge, with one line for each service that ran.
2. **Automatic top ups run next.** If the charge left the balance below your
   threshold, [automatic top ups](/docs/spend/credit#automatic-top-ups) add
   credit, with the same settings as for model use.
3. **If the balance is still below zero, machines stop.** Every running machine
   on the account is stopped, and new machine starts are refused until the
   balance is $1 or more.

An hourly charge is always taken in full, even when it is more than the balance,
so the balance can go below zero.

### When machine starts are paused

While starts are paused, a request to a service that is asleep is refused with
`402`:

```json
{
  "success": false,
  "error": "Machine starts are paused for this account: its credit balance went below zero. Machines start again once the balance is $1 or more. Add credit and the service starts on the next request."
}
```

Adding credit is enough to end the pause. The next start checks the balance and
goes ahead once it is $1 or more. Nothing else needs to be switched back on.

**Model work shares the balance.** An hourly charge for machine time can also
take the balance low enough that model work is refused for low credit. See
[When the balance runs low](/docs/spend/credit#when-the-balance-runs-low).

## Worked examples

**An office that works in bursts.** A `pro` office ($0.25 per hour) with a
20 minute idle timeout gets a message, works for 10 minutes, and then has no more
work. It runs for 30 minutes: 10 working and 20 waiting for its timeout.
That is $0.125.

**An office kept awake.** The same office with an idle timeout of `0` runs all
month: 730 hours, $182.50.

**A web service kept awake.** A web service at the default size ($0.0668 per
hour) with an idle timeout of `0` runs all month: 730 hours, $48.73.

**The same web service, sleeping.** With the default 20 minute timeout, it gets
requests between 9:00 and 17:00 on 22 working days and nothing at night. It runs
about 8 hours and 20 minutes each of those days: about 183 hours, $12.25.

**A size change partway through a month.** A web service runs at 1 vCPU, 2 GB for
the first 15 days, then is resized to 2 vCPU, 4 GB ($0.1260 per hour) and
deployed again, and runs for the rest of the month. About 365 hours at $0.0668
and 365 hours at $0.1260: about $70.37.

## Seeing what you have spent

The console shows machine time on the Billing page and on each service's Usage
tab, broken down by service. Each office is matched to its employee, so you can
see which employee a cost belongs to.

There are two kinds of figure, and only one of them is money:

| Figure | What it is | Up to date to |
| --- | --- | --- |
| **Charged** | What was taken from your credit, hour by hour | The last hour charged. The newest hour can be up to about an hour behind |
| **Estimate** | Running time so far, priced at today's price | Running time is recorded every five minutes, and once more when a machine stops |

For what you paid, use the charged figures:

| To see | Call |
| --- | --- |
| Each service's charge for each hour | [List compute charges](/docs/api-reference/billing/compute/listComputeCharges) |
| Charges over a window, for a chart | [Get a compute charge series](/docs/api-reference/billing/compute/getComputeChargeSeries) |
| Each hourly charge, with the balance before and after and what top ups did | [List compute bills](/docs/api-reference/billing/compute/listComputeBills) |
| What each service was charged over a window | [Get compute charges by service](/docs/api-reference/billing/compute/getComputeByService) |
| One service's charges and its employee's model use, together | [Get usage for one service](/docs/api-reference/billing/compute/getComputeServiceUsage) |

[Get estimated compute spend](/docs/api-reference/billing/compute/getComputeSpendSummary)
is the running time estimate. Use it to see what is running now, not to answer
what you paid.

All of these need `billing:read` at `console`.

## Keeping the cost down

<Callout type="warn">
  **No budget caps machine time.** A budget covers model use only. A service kept
  awake, or one that keeps receiving work, keeps costing until it stops. The only
  automatic stop is your credit balance going below zero, which stops every
  machine on the account.
</Callout>

Two settings decide what a service costs, and they are the only levers:

| Lever | Effect |
| --- | --- |
| A smaller [size](/docs/cloud/sizes) | A lower hourly price |
| A shorter [idle timeout](/docs/cloud/scaling#idle-timeout) | Fewer hours awake after the last piece of work |

An idle timeout of `0` keeps a machine awake and bills every hour of the month.
Use it only for a service that has to answer at once.

Change both in the console, or with
[Change a service's settings](/docs/api-reference/billing/compute/updateComputeServiceConfig).
